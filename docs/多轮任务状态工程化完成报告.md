## 2. 状态契约：新增的三个槽位

```python
# ---- 多轮任务上下文（槽位填充）----
pending_intent: NotRequired[Intent | None]   # 待办任务的意图；None = 没有未完成任务
pending_slot:   NotRequired[str | None]      # 待补齐的槽位名；None = 不缺槽位
pending_value:  NotRequired[str | None]      # 上一轮补齐的槽位「值」；被消费一次即置回 None
```

| 字段 | 写入者 | 清空者 | 语义 |
|---|---|---|---|
| `pending_intent` | `task_slot`（写待办时） | `task_slot`（补齐 / 取消时） | 待办任务属于哪个意图，用来在补齐那一轮**恢复**意图 |
| `pending_slot` | `task_slot`（写待办时） | `task_slot`（补齐 / 取消时） | 缺哪个槽位。**同时是条件边的判据**：非空 ⇔ 正在等用户补槽位 |
| `pending_value` | `task_slot`（补齐时） | `tool_agent`（消费一次即清空） | 补齐后的槽位值，交给下游 Agent 当成任务上下文 |

三个字段全部 `NotRequired`：未赋值时不影响图运行，因此**单轮链路与既有全部用例的行为逐字节不变**
（`agent_graph` 模块级实例、无 checkpointer 的直接调用都照常）。

为什么 `pending_value` 只有一个「值」而不是 `{slot: value}`：本阶段只有一个槽位，
归属由 `slots.slot_hint()` 单点解释；出现第二个槽位时**必须**升级成映射结构。
这条边界写在 `slots.py` 的模块 docstring 里，避免以后靠猜。

## 3. 拓扑变化：条件边的「源」前移一个节点

```
改前：START -> intent_router -> (条件路由 route_by_intent) -> chat / knowledge / agent / unknown -> END
改后：START -> intent_router -> task_slot -> (条件路由 route_after_task_slot) -> 同上 / END（只追问）
                                              agent <-> tools（官方 ToolNode，ReAct 回边不变）
```

`route_after_task_slot` 只有一条新规则：

```python
if state.get("pending_slot"):      # 正在等用户补槽位
    return END                     # 本轮唯一的产出就是那句追问
return route_by_intent(state)      # 其余情况：路由逻辑与改造前完全一致（同一个函数）
```

**职责边界没有变**：

- `intent_router` 仍然只做「判定 + 写 `state["intent"]`」，不跳转；
- 跳转仍然只由条件边决定，`route_by_intent` 本体一行未改（既有用例 `test_route_by_intent_still_maps_branches` 继续通过）；
- 只是「本轮真正要做的事」需要等待办任务并进来才能定，所以判据节点往后挪了一个。

`task_slot` 节点不调用模型、不执行工具、不发网络请求（由守卫用例扫描源码强制）。
追问是**确定性文案**，因此「缺学期」这一步一次模型调用都不花——这是刻意的工程化收益。

## 4. 缺槽位识别口径（有意收窄到三条规则）

`missing_slot(text, intent)` 只在**同时**满足三条时才返回 `semester`：

1. `intent == "query"`；
2. 文本里出现「成绩」或「分数」；
3. 文本里**没有**学期信息（显式 `2025-2026-1` 或「本学期 / 上学期」），**也没有**其它教务数据域
   （课表 / 课程 / 上课 / 考试 / 考场 / 教室 / 教师 / 老师 / 星期 / 周几 / 第几周）。

三个取舍，都是**为了不打断用户已经说完整的请求**：

| 取舍 | 原因 |
|---|---|
| 触发词只收「成绩」「分数」，不收「分」「考」 | 「数据结构考了多少分」已经带了课程范围，本身能作答，不该被拦下追问 |
| 多域请求不追问 | 「课表、考试、成绩都给我」很常见；拦下来问学期会把用户已说出的另外几项丢掉，比少追问更糟 |
| 学期判不出就返回 `None`（继续追问）而不猜 | `2025-2030-1`（学年不连续）、`2025-2026-12`（序号非法）都判不出；宁可再问一次，也不要按错学期去查 |

| 输入（`intent=query`） | 是否追问 | 原因 |
|---|---|---|
| 帮我查一下成绩 | ✅ | 只有成绩、没有范围 |
| 我想看下分数 | ✅ | 同上 |
| 数据结构考了多少分？ | ❌ | 含「分」但不含「成绩/分数」，已带课程范围 |
| 上学期成绩如何 / 这学期成绩怎么样 | ❌ | 已给学期 |
| 帮我看看课表和成绩 | ❌ | 多域请求 |
| 课表、考试、数据结构成绩都给我 | ❌ | 多域请求（**既有回归用例里的原句**） |
| 图书馆几点开门 | ❌ | 不是成绩问题 |

学期解析本身只支持三类输入（与需求一致，不多做）：显式串 → 「上学期」系列（当前学期的上一个学期）
→ 「本学期」系列（当前学期）。「当前学期」仍然只有 `app.tools.score_tools.CURRENT_SEMESTER` 一个来源，
`slots.current_semester()` 惰性引用它，不新建第二份日历常量。

## 5. 完整链路（一个环节都没有被绕开）

```
HumanMessage("上学期")
  -> LangGraph: intent_router（孤立识别 = unknown）
  -> LangGraph: task_slot（待办命中 -> semester=2024-2025-2，intent 恢复为 query）
  -> LangGraph: agent（系统提示 + 一句任务上下文）
  -> 模型自己产出 tool_calls: get_score(semester="2024-2025-2")
  -> LangGraph: 官方 ToolNode 执行工具
  -> MCP Tool（CAMPUS_MCP_ENABLED=true 时）-> MCP Server -> CampusApiClient
  -> Spring Boot /api/scores -> MySQL
  -> ToolMessage（真实四字段数据）-> agent -> 最终自然语言回答
```

三处刻意的设计：

1. **Agent 仍然是决策者**：`task_slot` 只提供「已确认学期是 X」这一个事实，
   调不调工具、参数怎么填，仍然由模型自己产出 `tool_calls` 决定；工具仍由官方 `ToolNode` 执行。
2. **上下文只随请求发出、不写回状态**：`slot_hint()` 的内容被追加进本轮的 `SystemMessage`，
   节点在返回时把 `pending_value` 置回 `None`。因此它既不会在 checkpointer 里逐轮堆积，
   也不会在工具回边后的第二次模型调用里重复出现（`test_task_context_is_handed_to_the_model_then_consumed_once`）。
3. **`pending_value` 为空时请求完全不变**：`_with_system_prompt(messages, None)` 的返回值与改造前
   逐字节相同，所以单轮链路零影响。

## 7. 真实联调结果

环境：`.env` 中 `CAMPUS_MCP_ENABLED=true`、`CAMPUS_SERVICE_BASE_URL=http://localhost:8081`、
Spring Boot 已启动（8081 可连）、MySQL80 运行中；模型 deepseek-chat。
（真实运行前先确认了端口与服务状态，不是「碰巧本机开着」。）

### 7.1 链路一：真实 CLI / REPL，同一 `--session-id` 连续两轮

```
CampusFlow 交互模式（会话 real-repl-multiturn）
意图识别完成: intent=query input='帮我查一下成绩'
本轮请求缺少槽位 semester，写入待办并追问
待办槽位 semester 未补齐，本轮只输出追问
CampusFlow[query] > 请问你要查询哪个学期的成绩？可以直接说「本学期」或「上学期」……

意图识别完成: intent=unknown input='上学期'          <- 孤立识别确实认不出这句话
槽位补齐: semester=2024-2025-2 -> 继续任务 query      <- 待办给了它含义
注入任务上下文: pending_value=2024-2025-2
模型请求调用工具: get_score
模型未请求工具，直接作答
CampusFlow[query] > 你上学期（2024-2025-2 学期）的成绩如下：
                   | 大学英语 | 86 | 2.0 |
                   | 高等数学 | 84 | 5.0 |
                   数据来源：校园教务系统实时查询。
调用工具：get_score
```

第一轮**只有一次意图识别调用**（没有任何工具调用），第二轮走完 `agent -> tools -> agent`。
`intent=unknown` 那一行是本阶段价值最直接的证据：**同一句话，没有待办时毫无意义，有待办时是一个完整任务**。

### 7.2 链路二：单进程、一个运行时、一个 checkpointer，两条 thread 交叉

```
[real-a] 用户: 帮我查一下成绩
  intent=query  tool_calls=[]
  回复: 请问你要查询哪个学期的成绩？……

[real-b] 用户: 上学期
  intent=unknown  tool_calls=[]                        <- 没有继承 real-a 的待办
  回复: [unknown] 该意图分支的拓扑已就绪，具体能力将在后续阶段接入。

[real-a] 用户: 上学期
  intent=query  tool_calls=['get_score']               <- 自己的待办被正确恢复
  回复: 你上学期（2024-2025-2 学期）的成绩如下（数据来自校园教务系统实时查询）：
       | 大学英语 | 86 | 2.0 |  | 高等数学 | 84 | 5.0 |
```

`real-b` 插在 `real-a` 两轮之间执行：它看不到 `real-a` 的待办，而 `real-a` 的状态没有被它影响——
**同 thread 恢复 + 跨 thread 隔离在同一次进程内同时被证到**（而不只是「换个进程内存自然是空的」）。

### 7.3 链路三：负向对照（证明数据确实来自 MCP -> 业务服务 -> MySQL）

把 `CAMPUS_SERVICE_BASE_URL` 指到 `http://127.0.0.1:9`（必然连接失败）后重跑同样两轮：

```
[neg-broken] 用户: 帮我查一下成绩 -> 请问你要查询哪个学期的成绩？……
[neg-broken] 用户: 上学期     -> tool_calls=['get_score']
  回复: 抱歉，查询上学期（2024-2025-2）成绩时，校园教务系统返回了服务暂时不可用的错误……

工具执行失败: MCPToolInvocationError: 校园 MCP 服务执行工具失败: 校园业务服务暂时不可用，请稍后再试。
  app/mcp/tools.py:212 -> self._client.call_tool(...)
  app/mcp/client.py:183 -> raise MCPToolInvocationError(...)
```

三点同时被证实：

1. 调用**确实经过 MCP**（异常类型与堆栈来自 `app/mcp/client.py`，不是直连工具）；
2. 数据**确实经过 HTTP 访问业务服务**（把地址改掉，数据就变成可读错误，回答里不再出现任何分数）；
3. **失败被隔离**：整轮对话没有崩，模型用自然语言解释了原因（既有 `handle_tool_error` 契约未被破坏）。

## 9. 遗留问题与后续建议

1. **`pending_value` 只有一个槽位**：只有 `semester` 一种槽位时「值 = 谁的」是确定的；
   出现第二种槽位（例如「哪门课」）前必须把它升级成 `{slot: value}`，
   否则会静默地张冠李戴。这条已写进 `slots.py` 的契约注释。
2. **多域请求不追问是有意妥协**：「课表 + 成绩」这类混合请求拿不到学期补齐。
   真要解决，正确方向是**按数据域拆任务**（一个请求里挂多个子任务），而不是把现在的规则放宽。
3. **待办没有过期 / 优先级**：目前只有「被 chat / knowledge / action 取代」这一条取消规则。
   用户连续说两句语义都不明确的话（`unknown`）时会持续追问。建议后续给待办加轮次上限或 TTL。
4. **跨进程不保留**：`CHECKPOINTER_BACKEND` 仍是 `memory`（`InMemorySaver`），
   因此多轮只在**同一进程**内有效（REPL 天然满足，单次 CLI 调用之间不保留）。
   生产化要切 Sqlite / Postgres 后端——`create_checkpointer()` 的登记表机制已经就位，图与节点无需改动。
5. **补齐轮的意图 tag 会「对不上」**：`intent_router` 先把**孤立识别**结果（`unknown`）
   追加成 run tag，随后 `task_slot` 才把意图覆盖为 `query`。因此那一轮在 LangSmith 里
   看到的 tag 是 `intent:unknown`，而实际执行的是 query 分支。
   这是刻意的（本阶段不动追踪代码），但要排查时需知道这一点：
   `app.agent.nodes.task_slot` 的 `槽位补齐: ... -> 继续任务 query` 日志才是那一轮的真实意图。
   后续若需要，可在 `task_slot` 里追加第二个 tag（`run_context.annotate_intent` 天然幂等，改动只有一行）。
6. **「上一学期」是日历推算，不是数据事实**：`previous_semester("2025-2026-1") -> "2024-2025-2"`
   依据的是学期串本身的编码规则。与 `CURRENT_SEMESTER` / `CURRENT_WEEK` 一样，
   接入真实校历接口后应交由服务端提供，`slots.py` 里只需替换 `current_semester()` 一处。
