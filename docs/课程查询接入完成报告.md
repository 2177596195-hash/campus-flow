## 2. `course_schedule` 表结构

```sql
CREATE TABLE IF NOT EXISTS course_schedule (
    id         BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
    student_id VARCHAR(64)  NOT NULL COMMENT '学号',
    course     VARCHAR(128) NOT NULL COMMENT '课程名称',
    teacher    VARCHAR(64)  NOT NULL COMMENT '任课教师',
    weekday    TINYINT      NOT NULL COMMENT '星期序号：1=周一 … 7=周日',
    class_time VARCHAR(32)  NOT NULL COMMENT '上课时段，形如 08:00-09:40',
    room       VARCHAR(64)  NOT NULL COMMENT '上课教室',
    week_start TINYINT      NOT NULL COMMENT '起始教学周（含）',
    week_end   TINYINT      NOT NULL COMMENT '结束教学周（含）',
    created_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    PRIMARY KEY (id),
    UNIQUE KEY uk_course_schedule_slot (student_id, course, weekday, class_time),
    KEY idx_course_schedule_student (student_id, weekday, class_time),
    KEY idx_course_schedule_weeks (week_start, week_end)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_general_ci COMMENT = '课程安排';
```

**三处与「最小字段清单」的有意偏离（都在 schema.sql 与实体注释里写明了理由）：**

1. **`weeks` 拆成 `week_start` + `week_end`**
   需求原文的最小字段里有 `weeks`。但 `weeks` 的语义是「区间」，而「第 3 周有什么课」
   必须在数据库里做范围比较才能用上索引。若存成 `"1-16周"` 字符串，过滤只能靠字符串
   解析，且把展示格式耦合进查询条件。因此**库里存区间上下界，展示串由 DTO 渲染**，
   输出格式与改造前的 mock 完全一致（`1-16周`），Agent 的回答措辞不会变形。

2. **`weekday` 存序号 1..7 而不是「周一」字符串**
   课表要按星期先后呈现，而中文「周一/周二/…」按字符排序得到的是
   「一、三、二、五、六、四、日」——完全乱序。存序号后数据库能排对，
   且「星期几」只有一种表示；对外展示的「周一」由 DTO 渲染。

3. **列名 `class_time` 而不是 `time`**
   `TIME` 是 MySQL 的数据类型关键字，避开它可以免掉跨驱动的标识符引用差异
   （Hibernate 是否加反引号在不同版本/配置下并不稳定）。对外字段名仍是 `time`。

**索引设计**：`(student_id, weekday, class_time)` 支撑「取某人课表并按星期、时间排序」；
`(week_start, week_end)` 支撑按周的范围过滤；唯一键
`(student_id, course, weekday, class_time)` 让 `data.sql` 可用 `INSERT IGNORE` 写成幂等的，
同时允许「同一门课排在不同星期」（数据结构周一 + 周四各一次，属真实课表常态）。

## 3. API

```
GET /api/courses?studentId=student-001
GET /api/courses?studentId=student-001&week=3
```

- `studentId`：**必填**。缺失时由 Spring MVC 自动返回 400。
- `week`：**可选**。`required = false`，不传即返回该学生全部课程；传了只返回
  「覆盖该周」的课程（`week_start <= week <= week_end`，闭区间）。
  非数字的 `week` 由框架类型转换失败处理，同样 400。
- **查不到返回 `[]`，HTTP 200**，不设计成异常（该学生这周没课是正常结果）。
  该周无课同样是 200 + `[]`。

响应体（DTO，只含 6 个字段）：

```json
[{"course":"数据结构","teacher":"李明","weekday":"周一","time":"08:00-09:40","room":"A302","weeks":"1-16周"}]
```

实体内部字段 `id` / `studentId` / `weekStart` / `weekEnd` / `classTime` / `createdAt`
一律不出现（有专门的用例守住）。

## 13. 当前遗留问题

1. **`CURRENT_WEEK = 3` 仍是 Python 侧常量。**
   它是**教务日历**概念（用于让模型把「这周/本周」映射成具体周次），不是课程数据，
   因此本阶段没被删除；但严格说它同样应该由服务端（校历接口）提供。
   本阶段的验证方式是把 `week` 显式传入——第 1 轮的 `week=3` 正是由它推导出来的。
   接入校历后应替换为一处配置或校历接口。

2. **`student_id` 仍绑配置值**（`CAMPUS_STUDENT_ID`，默认 `student-001`），
   尚无登录态/多用户身份；`student-002` 只能通过环境变量或换库来验证。

3. **`weeks` 只支持单区间。** 真实课表常有「1-8,10-16 周」这种断续区间，
   当前模型（一个 `week_start`/`week_end`）表达不了。需要时改法明确：
   加一张 `course_week` 明细表或存位图，DTO 层再合并成展示串。

4. **`weekday` 用的是自然周序号（1-7），不含单双周与节假日调休**；
   单双周需与第 3 点一起设计。

5. **`get_score` 仍是本地 mock**（本阶段明确禁止接入），是 `AGENT_TOOLS` 里最后一个
   未接真实的工具。

6. **无缓存 / 无重试熔断 / 无分页**：每次提问都是一次实时 HTTP 查询；
   课表数据量小，本阶段不需要，但学期初高并发下需要评估。

7. **性能与运维**：`mvn package` 会因运行中的进程占用 jar 而 repackage 失败
   （`Unable to rename ...jar to ...jar.original`），必须**先停服务再打包**；
   另外离线（`-o`）模式下 jar 插件依赖不全，需联网拉取一次。
   这两点已记入项目记忆。

8. **`campus_test` 库不随启动自动建表**（`sql.init.mode=never`），
   新增表结构后必须手动应用 `schema.sql` 到测试库，否则 Java 用例会报
   「表不存在」。这是既有设计（避免测试互相 DDL），但新增表时容易踩。
